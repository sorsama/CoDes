# Security Model

This document describes the security boundaries and trust assumptions in CoDes.

## Overview

CoDes follows a **least-privilege** design: each component has only the access it needs, and no component is implicitly trusted with another's secrets.

## Credential Isolation

### Provider Credentials

- CoDes **never stores** provider credentials (API keys, tokens, session auth).
- Each provider CLI retains ownership of its own authentication, typically stored in its own config files or system keychain.
- CoDes launches provider CLIs via PTY — it can send text input and read output, but does not extract or persist authentication material.

### Usage API Connectors

- Optional API keys for Usage Inspector connectors (OpenAI, Anthropic, GitHub, Google) are stored in the **OS credential vault** via the `keyring` crate.
- Keys are never written to CoDes configuration files, SQLite database, or log files.
- Workspace snapshots retain only connector metadata (which connectors are configured, last refresh time), never the keys themselves.

## Git Safety

### Structured Commands

All Git operations use structured argument passing:
- Repository path is validated against known project roots
- Branch names, file paths, and commit messages are validated before use
- Shell injection through Git arguments is prevented

### Disabled Operations

The following operations are intentionally **unavailable** in the Git workbench:
- **Force push** — cannot overwrite remote history
- **Hard reset** — cannot discard working tree changes destructively
- **Automatic conflict resolution** — all conflicts require manual review
- **Silent inclusion of unreviewed files** — every staged change is visible

### AI Commit Proposals

- Proposals run in **plan** mode (read-only) by default
- The diff sent to the provider is the exact staged diff the user sees
- "Verify first" mode requires user approval before committing
- "Full auto" has a configurable bounded execution limit

## Webview Isolation

### Browser Preview

- Remote pages load in a **separate Tauri child-webview process**
- The webview has **no general application IPC bridge** — it cannot call Tauri commands
- Rendered pages cannot:
  - Read local files outside the webview
  - Access the Zustand store or application state
  - Communicate with provider sessions
  - Access the file system
- Iframe fallback has the same security properties

### No General Bridge

Unlike many Tauri apps, CoDes does not expose a generic `invoke` bridge to arbitrary web content. Each IPC call is invoked explicitly from trusted React code, not from dynamic or remote content.

## Sharing Encryption

### WebRTC Data Channels

- All session data transmitted during sharing is encrypted with **AES-GCM** (256-bit key)
- Encryption keys are derived from the room secret, which is randomly generated by the host
- The encrypted channel carries terminal output and (optionally) input

### Signaling Relay

- The relay **never sees unencrypted session data**
- Signaling messages (WebRTC negotiation) are the only content the relay processes
- The relay is **memory-only** — it stores nothing to disk
- Rooms **expire** after inactivity (default 5 minutes)
- **Rate limiting** prevents abuse (configurable max messages/second)
- **Payload size limits** prevent resource exhaustion
- The relay does not authenticate beyond the room secret — security relies on the secret being shared out of band

### Remote Input

- Remote terminal input is **rejected by default**
- The host must explicitly grant **write permission** per sharing session
- Write permission can be revoked at any time

## Full Access Mode

- "Full Access" maps to each provider's bypass flag (`--yes`, `-y`, `--no-confirm`)
- This mode is **intentionally explicit** — it requires the user to choose it per session
- It should only be used in trusted or externally sandboxed environments
- It is never the default mode for any session

## Provider History Files

- History files on disk are **read-only inputs** — CoDes never modifies them
- Handoff previews:
  - **Exclude** hidden/system files
  - **Redact** likely credential patterns by default
  - **Report clearly** when history is unavailable, ambiguous, malformed, or permission-denied (no silent failures or fabricated data)

## Update Signing

- The updater plugin is intentionally **disabled in development**
- For production use, the following must be configured:
  - Tauri updater public key and endpoint
  - `tauri-plugin-updater` registered in the Rust builder
  - Associated capability granted
  - `bundle.createUpdaterArtifacts` enabled
  - GitHub release signing key, Windows signing certificate, and Apple signing/notarization secrets
- CoDes does **not** ship with a generated or placeholder signing identity
