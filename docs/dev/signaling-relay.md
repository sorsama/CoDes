# Signaling Relay

The signaling relay is a self-hostable WebSocket server that facilitates initial connection negotiation for CoDes's encrypted peer sharing feature.

## Overview

The relay acts as an opaque intermediary during WebRTC peer discovery:

```
Host ──WS── Relay ──WS── Peer
  │                      │
  └────── WebRTC ────────┘  (direct, after signaling)
```

Key characteristics:
- **Memory-only** — no persistence to disk
- **Expiry** — rooms expire after inactivity
- **Rate-limited** — prevents abuse
- **Validates payloads** — drops malformed messages
- **No stored messages** — rooms and invitations are never persisted

## Running the Relay

### Locally

```sh
cd services/signaling
npm install
npm run build
npm start
```

Starts on port 3000 by default.

### Via Docker

```sh
cd services/signaling
docker build -t codes-signaling .
docker run -p 3000:3000 codes-signaling
```

### From the CoDes workspace root

```sh
npm run relay:dev
```

## Configuration

The relay accepts environment variables:

| Variable | Default | Description |
|---|---|---|
| `PORT` | `3000` | HTTP/WebSocket listen port |
| `HOST` | `0.0.0.0` | Bind address |
| `RATE_LIMIT` | `100` | Max messages per second per connection |
| `ROOM_TTL` | `300000` | Room expiry in milliseconds (5 minutes) |
| `MAX_PAYLOAD_SIZE` | `65536` | Maximum message payload size in bytes |
| `MAX_ROOMS` | `1000` | Maximum concurrent rooms |

## Protocol

### WebSocket Messages

The relay handles a simple JSON message protocol:

**Client → Relay:**
```json
{ "type": "create_room", "room": "<room_id>", "secret": "<random_secret>" }
{ "type": "join_room", "room": "<room_id>", "secret": "<room_secret>" }
{ "type": "signal", "room": "<room_id>", "data": { <WebRTC signaling data> } }
```

**Relay → Client:**
```json
{ "type": "room_created", "room": "<room_id>" }
{ "type": "peer_joined", "room": "<room_id>" }
{ "type": "signal", "room": "<room_id>", "data": { <WebRTC signaling data> } }
{ "type": "error", "message": "..." }
```

### Room Lifecycle

1. Host sends `create_room` with a random room ID and secret
2. Relay creates the room, returns `room_created`
3. Host shares the room ID + secret out of band
4. Peer sends `join_room` with the room ID and secret
5. Relay notifies the host with `peer_joined`
6. Host and peer exchange WebRTC signaling via `signal` messages
7. WebRTC data channel opens directly between peers
8. Room expires after `ROOM_TTL` or when both peers disconnect

## Security

- The relay never sees session data — all content is AES-GCM encrypted before reaching the relay
- Room secrets are randomly generated by CoDes, not the relay
- Payload size is limited to prevent abuse
- Rate limiting prevents DoS attacks
- No persistence means no disk泄露 of room metadata
- The relay does not authenticate beyond the room secret

## Deployment

For production, deploy behind a reverse proxy (nginx, Caddy) with:
- TLS termination (WSS instead of WS)
- Optional IP allowlisting for private deployments
- Health check endpoint at `GET /health`

Example nginx config:

```nginx
server {
    listen 443 ssl;
    server_name relay.example.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
```
